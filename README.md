# Двойник

**Синтетическая аудитория для предварительной проверки банковских предложений.**

Продуктовая команда описывает несколько вариантов продукта или коммуникации, задаёт аудиторию
и сравнивает ответы цифровых персонажей по сегментам: готовность подключить предложение,
возможные причины отказа и синтетические объяснения. Результат можно сохранить, сопоставить
с другим запуском и проверить на загруженном опросе.

## Какую задачу решаем

Перед запуском банковского предложения команда выбирает, какие варианты и сегменты проверять
в интервью, опросах и A/B-тестах. «Двойник» даёт среду для предварительного сравнения гипотез
и подготовки этих исследований. Первый фокус — **текстовые предложения и коммуникации**.

Пользователи: продуктовые менеджеры, маркетинг и UX/CJM-исследователи банка.
Ожидаемая ценность — быстрее готовить проверки и исследовать больше вариантов до запуска.
Экономию времени и качество ранжирования предстоит измерить в пилоте.

## Что уже работает в MVP

| Возможность | Реализация |
| --- | --- |
| Конструктор исследования | Семь шаблонов или собственный сценарий, 2–5 предложений, вопрос и контекст |
| Настройка аудитории | Семь синтетических сегментов, доли и точное число профилей; 50–1000 двойников в UI |
| Симуляция | Демо без внешних запросов и подключение OpenAI-совместимого LLM API; одинаковые профили для вариантов |
| Аналитика | Матрица «сегменты × предложения», разбор выбранной аудитории, доли согласий, причины отказа и объяснения |
| Проверка опросом | Загрузка CSV, ошибка долей, сравнение рангов и лидера; сохранение проверки вместе с запуском |
| Архив и сравнение | Поиск, фильтры, сравнение двух запусков, повторное использование сценария, импорт/экспорт JSON и CSV |
| Доступ команды | Локальные аккаунты, роли, отдельные архивы владельцев и отзыв доступа к скачиваниям |

Код и рабочий процесс проверены автоматическими тестами и в браузере. Автоматические проверки
используют демо и изолированный HTTP-транспорт; это не проверка точности реальной модели.

## Попробовать без аккаунта, API-ключа и GPU

Нужны Git и Python **3.11 или 3.12**. Команды для macOS/Linux:

```bash
git clone https://github.com/NikitaMeshDS/dvoinik.git
cd dvoinik
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
DVOINIK_AUTH_MODE=demo python serve.py
```

Откройте **http://127.0.0.1:8501/** на том же компьютере.
В демо вход не требуется, внешние LLM отключены, используется отдельный локальный архив.
Если порт занят, добавьте `DVOINIK_PORT=8502` перед `python serve.py` и откройте соответствующий адрес.
Это локальное приложение; размещённого публичного веб-демо пока нет.

Для рабочего режима с аккаунтами, Windows и подключения LLM см. [инструкции запуска](docs/development.md).

## Сценарий демонстрации

1. Выберите «Вклад для пенсионеров»: три предложения отличаются каналом оформления и дополнительной защитой.
2. Посмотрите состав аудитории, запустите 200 двойников и сравните варианты в матрице.
3. Выберите сегмент для разбора графика и синтетических объяснений.
4. Нажмите «Использовать как основу», измените предложение и повторите запуск; сравните исследования.
5. Скачайте JSON. Для демонстрации импорта можно использовать [готовый демо-отчёт](examples/senior-deposit.demo.json).

Подробный [маршрут демо](docs/demo.md) включает загрузку настоящего опроса, когда ответы респондентов доступны.
Пример из репозитория не содержит результатов живой проверки.

## Что ещё предстоит подтвердить

- **Поведение людей:** ответ персонажа «да» — синтетическое намерение, а не факт оформления продукта.
- **Калибровку:** доли и характеристики сегментов сейчас основаны на экспертных предположениях.
- **Качество прогноза:** независимое сравнение с живыми респондентами и результатами прошлых запусков пока не проведено.
- **Скорость и экономику:** сроки, стоимость LLM-запуска и экономия времени команды зависят от сценария и инфраструктуры; измерение планируется в пилоте.
- **Банковское внедрение:** корпоративный SSO и развёртывание в контуре банка — следующие этапы.

Тестирование экранов по скриншотам и последовательных действий клиента пока не реализовано.
95% интервалы в отчёте описывают ответы симуляции и не измеряют точность предсказания людей.

## Следующий этап

1. Интервью с продуктовыми командами и выбор одного сценария первого пилота.
2. Популяция 200+ персонажей, проверяемые источники характеристик и первая разведочная проверка на опросе 30+ человек.
3. Фиксация настроек до проверки, сравнение с простым LLM-подходом и оценка ошибок ранжирования.
4. При подтверждении полезности — ретро-тест с продуктовой командой банка, затем сетевое развёртывание и тестирование экранов.

Целевой партнёр для пилота — продуктовая команда ВТБ. Согласованный пилот и достигнутые бизнес-результаты не заявляются.

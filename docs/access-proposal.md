# Доступ к исследованиям

Статус: локальные аккаунты, изоляция владельцев и отзыв одноразового экспорта реализованы.
Корпоративный OIDC/SSO остаётся следующим этапом.
Цель — дать команде доступ к сервису с отдельными учётными записями и предотвратить
чтение или изменение чужих исследований. Это не подтверждает готовность прототипа к эксплуатации банком.

## Выбор входа

| Вариант | Когда применять | Что потребуется |
| --- | --- | --- |
| Локальные учётные записи | Проверка прототипа небольшой командой без провайдера входа | Создание пользователей администратором, хеши паролей, ограничение попыток, срок сессии |
| Корпоративный SSO через OIDC | Банковский пилот с готовым провайдером | Провайдер, настройки клиента и callback, список разрешённых пользователей |
| Только локальное демо | Пока работает один автор на своём компьютере | Ограничить доступ сервером на localhost; архив останется общим |

Для банковского пилота предпочтителен корпоративный SSO. Streamlit уже поддерживает
[OIDC, вход и выход](https://docs.streamlit.io/develop/concepts/connections/authentication),
но проверку доступа к исследованиям приложение должно выполнять самостоятельно.
Если провайдера сейчас нет, локальные аккаунты могут быть промежуточным вариантом для прототипа.
Самостоятельная регистрация, социальный вход, рассылка писем и восстановление пароля по email
в первую версию не входят.

## Общие требования к доступу

1. До подтверждённого входа не загружать архив, не выдавать отчёты и не запускать LLM.
2. Идентификатор владельца определяется проверенной серверной сессией. Поля JSON,
   параметры URL и значения формы не могут назначать владельца.
3. Каталог, просмотр, сохранение опроса, сравнение и экспорт проверяют владельца на сервере.
   Скрытие кнопок само по себе не является проверкой доступа.
4. Администратор управляет учётными записями; эта роль не должна автоматически давать
   доступ ко всем исследованиям. Совместные проекты и выдача доступа коллегам — отдельное расширение.
5. Выход очищает черновики, активный отчёт и ожидающие записи этой сессии. Следующий пользователь
   в том же браузере не получает предыдущие данные. Перед выходом при несохранённых записях
   предлагается скачать отчёт или вернуться к работе.
6. Блокировка пользователя и изменение пароля должны прекращать доступ существующих сессий;
   истечение сессии не выполняет ожидающие записи и не запускает симуляцию.
7. Ошибка настройки входа закрывает доступ; автоматического перехода в общий архив быть не должно.

Для локальных аккаунтов: пароли задаются через скрытый ввод администратора, не через аргумент
командной строки и не через Git. В архиве хранится только хеш с солью. Рекомендуемый алгоритм —
[Argon2id по рекомендациям OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
Для сетевого доступа необходим HTTPS; демо без входа должно быть отдельным явно включённым режимом.

## Перенос существующего архива

Старые записи не имеют владельца. Перед миграцией создаётся резервная копия SQLite.
Существующие записи сохраняются в разделе без назначенного владельца, который обычным
пользователям недоступен. Администратор явно назначает владельца командой миграции.
Первый вошедший пользователь не получает старый архив автоматически.

При импорте JSON создаётся новая запись текущего пользователя. Исходный ID сохраняется
как происхождение импорта; поля владельца из файла не используются. Импорт не изменяет владельцев и не выдаёт доступ к другим записям.
Текущая защита от конфликтов сохранения опроса сохраняется отдельно от проверки владельца.

## Граница экспорта

Экспорты подготавливаются в проверенном пространстве владельца. `serve.py` запускает отдельный
HTTP endpoint на localhost; отчёты не отправляются в публичный `/media/` Streamlit.
Ссылка содержит случайный одноразовый handle, в базе хранится его хеш. Срок — 15 минут;
каждый запрос проверяет связанную сессию. GET атомарно погашает ссылку, HEAD проверяет без погашения.
После выхода, блокировки, смены пароля или истечения сессии файл недоступен.
Ссылка является bearer-секретом: получивший её может скачать файл один раз, пока сессия активна.
Общий доступ к отчётам через пересылку ссылок не предусмотрен. Выдача ограничена 10 МБ,
ответы имеют no-store/no-referrer/nosniff, URL не пишутся в журнал endpoint.
При повторном рендере погашенные ссылки заменяются; для повторного скачивания без иных действий
есть кнопка «Обновить скачивания».

## Проверка результата

- Два пользователя видят независимые архивы; чужой ID не позволяет читать, сравнивать,
  изменять или экспортировать исследование.
- Смена пользователя и выход не оставляют чужих черновиков, отчётов и файлов скачивания.
- Истёкшая или заблокированная сессия не обращается к данным и модели.
- Неверный пароль, превышение попыток и отсутствие настроек не открывают общий архив.
- Миграция сохраняет число записей, результаты и проверки; возможен возврат из резервной копии.
- Браузерные проверки входа выполняются с отдельными тестовыми аккаунтами, а не с паролями пользователей.

Следующий этап: корпоративный OIDC-провайдер, HTTPS/шлюз и правила совместного доступа для пилота.
Текущая проверка — автоматические тесты доступа/HTTP, браузер с двумя тестовыми аккаунтами
и независимое ревью с воспроизведением и исправлением найденных ошибок. Это не банковская сертификация.

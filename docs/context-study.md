# Проверка профиля и диалога на сценарии вклада

Проверяем, меняет ли профиль оценку готовности открыть вклад и помогают ли два уточнения приблизить оценки и причины отказа к ответам людей 60+. Условия вымышленного вклада одинаковы. В A открыть вклад можно только в приложении, в B — только в отделении.

## Прогон модели

```bash
LLM_BASE_URL=http://127.0.0.1:1234/v1 \
LLM_MODEL=qwen/qwen3-30b-a3b-2507 \
LLM_JSON_MODE=text \
LLM_EXTRA_BODY='{"chat_template_kwargs":{"enable_thinking":false}}' \
python context_study.py --n 16 --seed 42 --output proof/context-study.json
```

Модель, вопрос, условия, список причин и температура одинаковы. Без профиля модель знает только возрастную группу. В режиме с профилем она видит синтетическую анкету клиента. В режиме диалога модель сначала отвечает на два нейтральных вопроса с этим же профилем. Затем мы показываем каждый вариант из одной и той же исходной истории, без ответа на другой вариант. Это отдельный эксперимент. Готовность считаем по прямым ответам «да/нет».

Отчёт содержит доли согласия, разницу B минус A, число ответов и частоты причин среди отказов. Сравнение режимов использует только профили с валидными решениями во всех шести сочетаниях режима и предложения. Покрытие по каждому сочетанию и разбивка по цифровым навыкам видны отдельно. Повторяющиеся ответы без профиля возможны, поскольку запросы в этом режиме одинаковы при фиксированном предложении. Число синтетических профилей показывает объём симуляции и не является размером опроса.

### Первый прогон

20 ноября 2026, Qwen3-30B-A3B-2507 в LM Studio, `seed=42`. Все 16 профилей дали валидные ответы во всех режимах. Доля «да» составила 0 из 16 по каждому варианту в каждом режиме.

| Режим | «Неудобный канал», приложение | «Неудобный канал», отделение |
| --- | ---: | ---: |
| Без профиля | 1/16 | 16/16 |
| С профилем | 12/16 | 10/16 |
| С профилем и двумя уточнениями | 15/16 | 10/16 |

Профиль и уточнения меняют распределение причин. В этой конфигурации бинарные оценки упёрлись в ноль, поэтому разницу между каналами по готовности измерить не удалось. Сравнение с опросом ждёт ответов участников.

## Опрос людей

1. До показа участникам сохраните отчёт модели и зафиксируйте аудиторию, способ набора, размер выборки или дату завершения. Набирайте участников 60+ с разным опытом использования мобильного банка. Запишите, как набирали людей и сколько пропустили вопрос или прекратили участие по каждому варианту.
2. Случайно распределите участников на A и B в равных пропорциях. Задайте каждому два вопроса ниже в одном порядке, затем покажите только назначенное предложение. Используйте одинаковый способ показа и формулировки. Ответы модели участникам не показывайте.
3. Задайте «Открыли бы вы этот вклад?» с вариантами «Да» и «Нет». При ответе «Нет» попросите выбрать одну главную причину. Если выбран вариант «другое», выгружайте только категорию.
4. Сохраните по одной записи на валидный ответ. Поля и категории ниже достаточны для сравнения. Имена, контакты и стенограммы в этот файл не включайте. Ответы людей обрабатываются локально, при сравнении запросов к модели нет.

Уточняющие вопросы

1. Как вы обычно решаете вопросы с банком? Кто-нибудь помогает вам с этим?
2. Что вам сложнее всего, когда вы хотите воспользоваться новой банковской услугой?

| Вариант | Текст для участника |
| --- | --- |
| A | Вклад на 6 месяцев под 15% годовых от 50 000 ₽. Открытие только в приложении банка. |
| B | Вклад на 6 месяцев под 15% годовых от 50 000 ₽. Открытие только в отделении банка. |

Причины отказа — «неудобный канал», «не подходят условия вклада», «не доверяю банку», «нет свободных денег», «сейчас не нужен вклад», «другое».

Формат данных. Строки ниже иллюстрируют поля.

```json
[
  {"variant": "A", "decision": false, "reason": "неудобный канал"},
  {"variant": "B", "decision": true, "reason": null}
]
```

```bash
python context_study.py --compare proof/context-study.json \
  --human /path/to/coded-responses.json --output proof/context-study-compared.json
```

Для каждого режима смотрите абсолютную ошибку доли «да» по предложениям и среднюю ошибку по A/B. Для отказов смотрите расстояние между распределениями причин — половину суммы абсолютных разностей долей по категориям, в п. п. Ноль значит, что распределения совпали. Если в одной из групп нет отказов, метрика отсутствует. Сравнивайте вместе с числом участников и отказов. Опрос измеряет заявленное намерение после уточняющих вопросов. Этот протокол показывает качество приближения к одному опросу и не измеряет, как сами уточнения влияют на ответы людей.

## Что теперь измеряет сценарий вклада

В шаблоне «Вклад для пенсионеров» можно задать общий минимальный взнос для всех предложений. По умолчанию он составляет 50 000 ₽. Модель отвечает на вопрос об интересе при условии, что нужная сумма есть. Цифровой навык остаётся в промпте. Доступная сумма хранится в синтетическом профиле и участвует в отдельной проверке в коде. Ровно минимальная сумма проходит проверку. Неизвестная сумма учитывается отдельно. Отчёт показывает финансовую доступность по всей синтетической аудитории и доли интереса среди валидных ответов каждого предложения.

Текущие уровни сумм — контролируемые значения для демонстрации, включая ноль и значение на границе. Реального распределения свободных средств они пока не отражают. Общий минимум входит в предложения модели и анкету для людей. Сравнивайте долю интереса с опросом, который использовал тот же гипотетический вопрос.

В комплекте опроса из такого снимка есть отдельный бланк для каждого варианта с сохранёнными условиями и минимальным взносом. Покажите участнику только назначенный бланк. CSV из комплекта группирует ответы по сегментам исследования. Для разреза по цифровому навыку используйте специальный протокол ниже. При сравнении двух снимков изменение минимального взноса отображается в условиях сравнения.

## Проверка влияния цифрового навыка

В новой серии банк, срок, ставка и сумма одинаковы. A открывается только в приложении, B — только в отделении. Вопрос отделяет интерес от наличия денег. Модель оценивает вероятность собственного ответа «да». Для каждого профиля, предложения и модели проводим два запуска. Промпты отличаются только наличием поля «Цифровые навыки». Оцениваем среднюю вероятность по каждому каналу и разницу A минус B в каждой группе навыков. Две новые выборки по 12 профилей с разными seed проверяются отдельно. В агрегат входят профили с ответами на оба канала в обоих режимах.

### Прогноз до сбора ответов

23 ноября 2026 года зафиксировали пару оценок для разведочного опроса 60+. Основная оценка «Двойника» использует профили с цифровым навыком из прогона Qwen3-VL-4B на 24 синтетических участниках. В простом промпте та же модель оценила по одной доле «да» для каждого предложения и группы по общему описанию. Дополнительный режим без поля цифрового навыка остаётся в отчёте как проверка влияния этого поля.

| Как пользуются мобильным банком | Профилей | Двойники A / B | Двойники A − B | Простой промпт A / B | Простой промпт A − B |
| --- | ---: | ---: | ---: | ---: | ---: |
| Самостоятельно | 6 | 66,7% / 42,5% | +24,2 п. п. | 85% / 30% | +55 п. п. |
| С помощью | 6 | 30,0% / 42,5% | −12,5 п. п. | 75% / 60% | +15 п. п. |
| Без интернета | 12 | 14,2% / 37,1% | −22,9 п. п. | 40% / 100% | −60 п. п. |

Положительная разница означает больший заявленный интерес к приложению. В основной паре сравниваем абсолютную ошибку разницы A − B внутри каждой группы на тех же ответах людей. Для группы с ответами только по одному предложению считаем ошибку доли, а разницу оставляем пустой. Анализ запланирован по группам. Единой оценки для всей аудитории пока нет. План набора и дата завершения опроса требуют согласования.

В тестовых запросах модель сначала повторила числа из примера формата, а без примера выдала доли, складывающиеся в единицу в каждой группе. До сбора данных уточнили независимость групп показа, убрали числовые примеры из промпта и включили JSON-схему. Параметры и точный запрос сохранены вместе с итоговым ответом. [Прогон двойников](benchmark-results/2026-11-20/deposit-digital-skill-4b.json) · [Оценка простым промптом](benchmark-results/2026-11-23/deposit-simple-prompt-4b.json)

### Анкета для прямой проверки

Бланки готовы к печати или переносу в нейтральную форму опроса. [Вариант A — приложение](deposit-pilot/A.html) · [Вариант B — отделение](deposit-pilot/B.html)

- Набирайте участников 60+ и заранее фиксируйте, где и как их набирали. Для группы без интернета используйте также очный способ набора. Зафиксируйте дату завершения или объём. Для разведочного прогона обязательно покажите число ответов по каждому каналу и группе.
- Назначайте по заранее подготовленной последовательности A/B. Покажите только назначенный бланк, одинаковым способом и без подсказок. Спросите о цифровом навыке после ответа про вклад. Сохраните отдельно число пропусков и ответов вне трёх заданных групп.
- Зафиксируйте локальные отчёты модели до сбора. В выгрузке одна строка на валидный обезличенный ответ. В колонке `segment` используйте `independent`, `assisted` или `offline` для первых трёх ответов о мобильном банке. В `decision` кодируйте «да» как 1, «нет» как 0. Пропуски в расчёт доли не входят. Схема без примеров ответов:

```csv
variant,segment,decision
```

```bash
python -m benchmarks.deposit_digital_skill \
  --compare docs/benchmark-results/2026-11-20/deposit-digital-skill-4b.json \
  --baseline docs/benchmark-results/2026-11-23/deposit-simple-prompt-4b.json \
  --survey /path/to/answers.csv --output proof/deposit-digital-skill-4b-compared.json
```

Сравнение выполняется по каждой группе и каналу. В `human_coverage` указано, сколько из шести сочетаний покрыто опросом, сколько можно сопоставить со всеми включёнными оценками и в каких группах можно сравнить разницу между каналами. Отдельные списки показывают сочетания без ответов людей и сочетания с ответами, для которых не хватило оценок модели. Покрытие показывает наличие данных. Объём выборки оценивайте по числу участников в каждом сочетании.

В `human_comparison` есть числа и доли ответов «да» и абсолютные ошибки. Если в группе есть ответы на A и B, скрипт показывает разницу A минус B в п. п. Положительная разница означает больший интерес к приложению. Для режима без нужных оценок модели разница и её ошибка останутся пустыми.

Для опроса с независимыми группами показа скрипт выводит 95%-й интервал A − B по методу Ньюкомба. `survey_gap_direction` показывает A или B, если весь интервал лежит по одну сторону нуля. Если интервал включает ноль, направление неопределённо и `model_direction_match` остаётся пустым. Интервалы рассчитываются отдельно для каждой группы и отражают выборочную неопределённость при независимых ответах. Общий вывод по аудитории и поправка на несколько сравнений в разведочном анализе не рассчитываются. [Метод Ньюкомба](https://pubmed.ncbi.nlm.nih.gov/9595617/)

Внешние исследования о выборе канала используйте для контекста. [Опрос «Синары»](https://sinara.ru/press-centr/news/2023/rossiyane-vybirayut-vklad-po-stavke-i-nadezhnosti-banka) и [опрос НАФИ о цифровых привычках людей старше 60 лет](https://nafi.ru/projects/finansovoe-povedenie-pozhilykh-v-kontekste-tsifrovizatsii/) не дают долей ответов на эти два предложения.

### Как назначить бланки

После согласования объёма сгенерируйте список назначений и сохраните его SHA-256 в карточке пилота. Число 30 в примере иллюстрирует команду. Целевой объём согласуется отдельно.

```bash
python -m benchmarks.deposit_assignments --n-per-variant 30 --output assignments.csv
```

В CSV есть только позиция `slot` и вариант `A` или `B`. Храните список у координатора. После проверки критериев участия координатор выдаёт следующий свободный бланк по порядку. Участнику показывают только назначенный бланк. После выдачи позицию считают использованной, даже если ответа нет. Не меняйте порядок из-за ранних ответов и не выдавайте пропущенный бланк заново.

В полном списке поровну A и B. При ранней остановке и пропусках число показов и ответов может различаться. Храните CSV назначений отдельно от регистра выдачи.

### Сверка назначений с ответами

Координатор ведёт регистр выдачи `issued.csv` со столбцами `slot,segment,decision`. Запишите одну строку на каждый показ, включая пропуск. Вариант определяется по исходному списку назначений. Оставьте `decision` пустым, если ответа на вопрос о вкладе нет. Оставьте `segment` пустым при ответе о вкладе вне трёх групп цифрового навыка. Позиции, которые ещё не выдали, в файл не вносятся. Номера заполняются с первой позиции без разрывов.

```bash
python -m benchmarks.deposit_digital_skill \
  --compare docs/benchmark-results/2026-11-20/deposit-digital-skill-4b.json \
  --baseline docs/benchmark-results/2026-11-23/deposit-simple-prompt-4b.json \
  --assignments /path/to/assignments.csv --assignment-sha256 "<согласованный SHA-256>" \
  --survey /path/to/issued.csv --output proof/deposit-pilot-compared.json \
  --summary proof/deposit-pilot-summary.md
```

В `assignment_reconciliation` сохраняются контрольная сумма списка и итоги по каждому варианту. В анализ долей попадают ответы «да» или «нет» с указанной группой. Пропуски и ответы без группы видны в итогах выдачи. Сверка проверяет уникальность позиции в регистре. Подтверждение того, что каждый человек участвовал один раз, остаётся частью процедуры набора.

Резюме Markdown содержит сводные числа по бланкам, наблюдаемую разницу с интервалом и ошибки прогнозов. Для прогона на синтетических ответах добавьте `--rehearsal`. Пометка сохранится в JSON и появится в начале резюме.

Для повторного экспорта используйте сохранённый результат. Исходный CSV и вызовы модели для этого не нужны, пометка о репетиции сохраняется.

```bash
python -m benchmarks.deposit_digital_skill \
  --summary-from proof/deposit-pilot-compared.json --summary proof/deposit-pilot-summary.md
```

Для нового сравнения с полевым опросом возьмите исходный прогноз двойников и утверждённый простой промпт.

### Результат контрольного прогона

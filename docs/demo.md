# Маршрут демонстрации MVP

[Описание продукта](../README.md) · [Полная настройка](development.md)

Это проверка рабочего процесса на синтетических данных. Ниже не представлены результаты
живого исследования, прогноз спроса или замер экономии времени.

## Запуск

Установите зависимости по README и запустите:

```bash
DVOINIK_AUTH_MODE=demo python serve.py
```

Откройте `http://127.0.0.1:8501/` на том же компьютере. Вход и ключи не нужны, GPU не нужен.
Демо использует `.data/demo.sqlite3` отдельно от архива аккаунтов, внешние LLM отключены.
В начале отображается пример, который автоматически не добавляется в историю.
Если в демо-архиве уже есть запуски, откроется каталог: перейдите в «Конструктор».

## Исследование: предложение вклада аудитории 60+

1. В конструкторе, в блоке «Настройки исследования» основной области рабочего пространства,
   выберите сценарий «Вклад для пенсионеров» и аудиторию 200.
2. Прочитайте три исходных предложения. A — оформление в приложении;
   B — отделение или менеджер; C — дополнительное подтверждение снятия родственником.
   Это разные предложения; разница A/C не является эффектом одной смены канала.
3. На вкладке «Состав аудитории» посмотрите точное число профилей. Обратите внимание на
   проверку готовности перед запуском.
4. Нажмите «Запустить эксперимент». В отчёте сохранены использованные тексты, состав и seed.
5. Сравните предложения в матрице: в каждой ячейке показаны доля «да» и покрытие ответов.
   В «Разобрать аудиторию» выберите сегмент: график и примеры объяснений относятся к нему.
   Верхняя сводка остаётся по всей аудитории. «Аудитория» и «Голоса двойников» дают больше деталей.
   Ответы синтетические; результат обусловлен правилами демо-движка.
6. Измените текст варианта B. Старый отчёт будет помечен как результат прежних настроек.
7. Повторите запуск и откройте «Сравнение». Сопоставьте тексты, условия и результаты.
   Дельты описательные, без вывода о причинном эффекте или значимости.
8. В «Исследованиях» найдите оба запуска и откройте сохранённый отчёт.
   «Использовать как основу» в начале отчёта копирует его снимок настроек в собственный сценарий.
   Можно начать следующую итерацию прямо из отчёта в конструкторе.
9. Скачайте JSON или CSV. Для повторного скачивания нажмите «Обновить скачивания».

## Посмотреть сохранённый пример

В репозитории есть [полный JSON демо-запуска](../examples/senior-deposit.demo.json).
Его можно прочитать на GitHub без запуска приложения или импортировать через раздел
«Исследования» → «Импорт исследования из JSON». Файл использует режим mock, seed 42,
200 синтетических профилей одного сегмента; живого опроса в нём нет.

Воспроизвести пример через CLI:

```bash
python cli.py senior_deposit --n 200 --mock --seed 42 --output report.json
```

Демо-ответы воспроизводятся при одинаковых текстах, коде и seed.
ID, время создания и время выполнения нового JSON отличаются; сравнивайте сценарий и ответы,
а не весь файл побайтово.

## Когда доступны ответы респондентов

Откройте «Валидацию» и скачайте шаблон CSV. Замените демонстрационные значения настоящими
ответами на те же тексты предложений. Формат: `segment,variant,decision`; `decision` — 0 или 1.
Для этого сценария сегмент — `senior`, варианты — A/B/C.
Загрузите CSV, изучите предпросмотр и явно сохраните проверку в эксперименте.

Загрузка файла показывает механизм сопоставления. Подлинность ответов приложение не проверяет;
наличие метрик в JSON само по себе не подтверждает точность модели.

## Что показывать на защите

Конструктор → состав аудитории → результат → объяснения → сравнение следующей итерации.
Отдельно обозначьте, что LLM-подключение реализовано, а представленное демо работает на эвристике.
Живую валидацию, калибровку и пилот представляйте как следующий эксперимент до появления реальных результатов.

# Маршрут демонстрации MVP

[Описание продукта](../README.md) · [Подробная настройка](development.md)

Это проверка рабочего процесса на синтетических данных; демо не является прогнозом спроса.

## Запуск

Установите Python-зависимости и соберите React по README, затем:

```bash
DVOINIK_AUTH_MODE=demo python serve.py
```

Откройте `http://127.0.0.1:8501/`. Вход и ключи не нужны, внешние LLM отключены.
Демо использует `.data/demo.sqlite3` отдельно от архива аккаунтов. В пустом каталоге
«Посмотреть пример исследования» открывает демонстрационный снимок без записи в историю.

## Предложение вклада аудитории 60+

1. Нажмите «Новое исследование», выберите «Вклад для пенсионеров».
2. Прочитайте тексты: A — приложение; B — отделение или менеджер;
   C — подтверждение снятия родственником. Это три предложения; разница A/C не является
   эффектом одной смены канала.
3. Нажмите «Далее: аудитория». Проверьте 200 профилей сегмента 60+.
   Seed, модель и параллельность доступны в раскрывающихся параметрах.
4. Запустите исследование. Прогресс показывает завершённые оценки движка.
5. В матрице сравните доли и валидные / запрошенные ответы. Нажмите название сегмента
   для разбора графика и объяснений; верхняя сводка остаётся по всей аудитории.
6. Посмотрите «Аудиторию» и «Голоса». Реплики синтетические, подборка не представляет все ответы.
7. Нажмите «Следующая итерация», измените B и повторите запуск.
   Исходный отчёт сохраняется; новая итерация копирует именно его снимок.
8. В меню каталога «…» выберите «Сравнить исследования», отметьте два запуска и нажмите «Сравнить».
   Дельта описательная, без вывода о причинном эффекте или значимости.
9. В меню отчёта «…» скачайте полный JSON или сегменты CSV. Каждый клик готовит новую
   одноразовую ссылку; отдельная кнопка обновления скачиваний не требуется.

## Импорт сохранённого примера

В меню каталога «…» выберите «Импорт JSON» и загрузите
[полный демо-отчёт](../examples/senior-deposit.demo.json). Он использует seed 42,
200 профилей 60+, режим mock и не содержит живого опроса.

Воспроизвести его через CLI:

```bash
python cli.py senior_deposit --n 200 --mock --seed 42 --output report.json
```

При одинаковых текстах, коде и seed демо-ответы воспроизводятся. ID, время создания
и выполнения отличаются; сравнивайте сценарий и ответы, а не файл побайтово.

## Проверка опросом

На вкладке «Проверка опросом» скачайте комплект ZIP: нейтральную HTML-анкету для браузера
и печати, инструкцию с кодами сегментов и пустой CSV. Тексты и коды также можно раскрыть
в интерфейсе. Запишите настоящие ответы на сохранённые предложения; добавляйте строки
для новых оценок и удалите незаполненные. Формат: `segment,variant,decision`;
`decision` — 0 или 1, для вклада сегмент `senior`, варианты A/B/C.
Шаблон CSV отдельно доступен в меню «Файлы проверки». Ячейки без валидных ответов симуляции
исключаются из шаблона; для их проверки нужно повторить запуск с нужным покрытием.
Загрузите CSV, изучите предпросмотр и нажмите «Сохранить проверку».

Предпросмотр сохраняется при переключении вкладок отчёта. Конфликт другой сессии
не перезаписывает серверную проверку; можно скачать полный предпросмотр и явно сверить
опрос заново. Новая загрузка заменяет прежний опрос. Число ответов считает оценки предложений,
а не уникальных людей. Подлинность ответов приложение не проверяет. Демо остаётся демо после загрузки CSV.

## На защите

Покажите создание → аудиторию → матрицу → объяснения → следующую итерацию → сравнение.
Обозначьте реализованное LLM-подключение и эвристический режим демонстрации.
Живую валидацию, калибровку и пилот представляйте как следующие эксперименты до появления результатов.

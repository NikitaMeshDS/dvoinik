# Маршрут демонстрации MVP

[Описание продукта](../README.md) · [Подробная настройка](development.md)

Это проверка рабочего процесса на синтетических данных; демо не является прогнозом спроса.

## Запуск

Установите Python-зависимости и соберите React по README, затем:

```bash
DVOINIK_AUTH_MODE=demo python serve.py
```

Откройте `http://127.0.0.1:8501/`. Вход и ключи не нужны, внешние LLM отключены.
Демо использует `.data/demo.sqlite3` отдельно от архива аккаунтов. В пустом каталоге
«Посмотреть пример исследования» открывает демонстрационный снимок без записи в историю.

## Предложение вклада аудитории 60+

1. Нажмите «Новое исследование», выберите «Вклад для пенсионеров».
2. Прочитайте тексты: A — приложение; B — отделение или менеджер;
   C — подтверждение снятия родственником. Это три предложения; разница A/C не является
   эффектом одной смены канала.
3. Нажмите «Далее: аудитория». Проверьте 200 профилей сегмента 60+.
   Seed, модель и параллельность доступны в раскрывающихся параметрах.
4. Запустите исследование. Прогресс показывает завершённые оценки движка.
5. В матрице сравните доли и валидные / запрошенные ответы. Нажмите название сегмента
   для разбора графика и объяснений; верхняя сводка остаётся по всей аудитории.
6. Посмотрите «Аудиторию» и «Голоса». Реплики синтетические, подборка не представляет все ответы.
7. Нажмите «Следующая итерация», измените B и повторите запуск.
   Исходный отчёт сохраняется; новая итерация копирует именно его снимок.
8. В меню каталога «…» выберите «Сравнить исследования», отметьте два запуска и нажмите «Сравнить».
   Дельта описательная, без вывода о причинном эффекте или значимости.
9. В меню отчёта «…» скачайте полный JSON или сегменты CSV. Каждый клик готовит новую
   одноразовую ссылку; отдельная кнопка обновления скачиваний не требуется.

## Импорт сохранённого примера

В меню каталога «…» выберите «Импорт JSON» и загрузите
[полный демо-отчёт](../examples/senior-deposit.demo.json). Он использует seed 42,
200 профилей 60+, режим mock и не содержит живого опроса.

В примере сохранена прежняя версия шаблона. Запустить актуальную версию через CLI:

```bash
python cli.py senior_deposit --n 200 --mock --seed 42 --output report.json
```

При одинаковых текстах, коде и seed демо-ответы воспроизводятся. ID, время создания
и выполнения отличаются; сравнивайте сценарий и ответы, а не файл побайтово.

## Что проверяют шаблоны

| Шаблон | Сравнение |
| --- | --- |
| Студенческая карта | Три пакета карты целиком. Вопрос учитывает, что подросток может обсуждать оформление с родителями. |
| Семейный счёт | A и B различаются видимостью личных трат. B и C различаются ценой при одинаковых возможностях. |
| Кредитная карта | Три формулировки одного льготного периода. Срок, ставка и условие погашения совпадают. |
| Вклад | A и B различаются каналом открытия, B и C — возможностью подключить защиту. Вопрос измеряет интерес при наличии нужной суммы. |
| Кэшбэк в пуше | Три подачи одного предложения. Вопрос измеряет заявленное намерение нажать на уведомление. |
| Тариф самозанятых | Три набора функций и условий оплаты. Сравнивается интерес к тарифам целиком. |
| Переводы | Один перевод на заданную сумму. A и B различаются языками интерфейса, B и C — комиссией. Для живой проверки наберите клиентов, которым подходит выбранное направление перевода. |
| Свой сценарий | Исследователь задаёт вопрос, предложения, категории отказа и состав аудитории. |

Контекст исследования — заметка для команды. Условия, необходимые участнику, укажите в вопросе
или тексте предложения. Каждый двойник видит один вариант за запрос. Для сравнения с ответами людей
используйте те же формулировки из сохранённого снимка.

## Анкеты до запуска

На шаге «Аудитория» откройте «Что увидит двойник» и выберите сегмент.
Локальная версия показывает одну анкету из текущей синтетической выборки.
Её текст создаёт тот же генератор, который использует запуск. При изменении
долей, размера или seed пример пересчитывается. Для вклада синтетическая сумма
видна отдельно, поскольку её использует расчёт доступности. В деморежиме
реакцию считает эвристика по сегменту и тексту предложения.

Внутри блока откройте «Текст запроса к модели» и выберите вариант. Видны текстовое
сообщение для этого предложения и общая инструкция модели. Демо показывает,
как выглядел бы запрос в режиме LLM, без отправки сообщения провайдеру.

## Проверка опросом

На вкладке «Проверка опросом» скачайте комплект ZIP с отдельным HTML-бланком на вариант,
инструкцией с кодами сегментов и пустым CSV. Случайно назначьте каждому участнику один бланк.
Тексты и коды можно раскрыть в интерфейсе. Запишите настоящие ответы на сохранённые предложения. Добавляйте строки
для новых оценок и удалите незаполненные. Формат: `segment,variant,decision`;
`decision` — 0 или 1, для вклада сегмент `senior`, варианты A/B/C.
Шаблон CSV отдельно доступен в меню «Файлы проверки». Ячейки без валидных ответов симуляции
исключаются из шаблона; для их проверки нужно повторить запуск с нужным покрытием.
Загрузите CSV, изучите предпросмотр и нажмите «Сохранить проверку».

В меню отчёта скачайте «Резюме для команды». Для сохранённого опроса в HTML
показаны до пяти самых крупных расхождений по парам «предложение — сегмент».
Для каждой пары видны доли опроса и симуляции, направление разницы и число
оценок. Полная таблица доступна в отчёте и в файле «Метрики JSON».
Чтобы сравнить предложения внутри группы, выберите сегмент над таблицей расхождений.
Фильтр меняет строки таблицы и доступные пары вариантов. Сводные метрики относятся ко всему загруженному опросу.
Если в сегменте оценили два предложения или больше, сравните выбранную пару.
Блок показывает разницу по опросу и по общим профилям симуляции в направлении «первый вариант минус второй». Для парной оценки указаны число общих профилей в выбранном сегменте и абсолютное расхождение с опросом. Старые снимки показывают разницу бинарных долей с соответствующей подписью.
Если в протоколе указано случайное назначение одного варианта каждому участнику,
рядом с наблюдаемой разницей виден 95%-й интервал Ньюкомба. Когда он включает ноль,
направление остаётся неопределённым. Для других способов назначения доступны
наблюдаемые доли и размеры групп. Интервалы рассчитываются по каждой паре отдельно.
При случайном назначении одного предложения на человека сводка также показывает
приблизительный 95%-й интервал средней абсолютной ошибки. Границы строятся из
[интервалов Уилсона](https://doi.org/10.1214/ss/1009213286) для долей опроса с поправкой
Бонферрони и теми же весами ячеек, что у средней ошибки. Расчёт предполагает независимые
ответы внутри ячеек и фиксирует доли симуляции и состав опроса. Смещение отбора
респондентов и разброс симуляции в интервал не входят.
Общий блок сравнения с простым промптом появляется, когда по всем предложениям
сегменты и их доли совпадают с аудиторией сохранённого простого промпта.
При другом составе или неизвестных долях остаются ошибки по сегментам и объяснение.



Предпросмотр сохраняется при переключении вкладок отчёта. Конфликт другой сессии
не перезаписывает серверную проверку; можно скачать полный предпросмотр и явно сверить
опрос заново. Новая загрузка заменяет прежний опрос. Число ответов считает оценки предложений,
а не уникальных людей. Подлинность ответов приложение не проверяет. Демо остаётся демо после загрузки CSV.

## На защите

Покажите создание → аудиторию → матрицу → объяснения → следующую итерацию → сравнение.
Обозначьте реализованное LLM-подключение и эвристический режим демонстрации.
Живую валидацию, калибровку и пилот представляйте как следующие эксперименты до появления результатов.

## Доработки второго спринта

- Измените текст и шаг мастера, обновите страницу: черновик восстанавливается в этой вкладке. При выходе из аккаунта он удаляется.
- Очистите обязательное поле и нажмите «Далее»: ошибка отображается рядом, фокус переходит к полю.
- В отчёте блок «Следующий шаг исследования» сначала предлагает восстановить запись/качество данных, затем подготовить живую проверку или разобрать загруженный опрос. «Следующая итерация» остаётся доступной отдельно.
- Перед заменой опроса видны дата старой проверки и число оценок до/после; доступен экспорт прежнего снимка. Несохранённый предпросмотр защищён от случайного ухода.

Полный маршрут защиты и открытые гипотезы: [реестр доказательств](sprint-2-evidence.md).

## Происхождение ответов опроса

Перед выбором CSV раскройте «Как собраны ответы»: можно указать способ набора,
период, распределение предложений и примечание. Поля необязательны; неизвестные
значения оставьте пустыми. Имена и контакты участников не нужны.

Сведения показываются в предпросмотре и сохраняются вместе с проверкой. Во время
предпросмотра редактирование заблокировано: отмените его, исправьте сведения и
выберите CSV заново. Отмена предпросмотра сохраняет введённые сведения, отдельная
кнопка очищает их. Уход с несохранёнными сведениями вызывает предупреждение.

Полный JSON, JSON метрик и HTML-резюме содержат протокол; CSV метрик остаётся таблицей.
Старый снимок без протокола сообщает, что сведения не сохранены. Приложение не проверяет
достоверность описания набора или уникальность участников.

## История проверок гипотезы

Во вкладке «Гипотезы» выберите изменение и запустите A/B-проверку. После завершения
вернитесь кнопкой «Открыть исходное исследование»: у соответствующей гипотезы появляется
список связанных запусков с датой, режимом, числом профилей и текстами A/B.

Новые запуски связываются устойчивым идентификатором гипотезы внутри исходного отчёта.
Ранг гипотезы и переписанный B не меняют эту связь. Изменённый A или состав аудитории
помечаются отдельно. Старые снимки связываются только при совпадении сохранённых
условий; совпадения названия рычага недостаточно. Связь не доказывает эффект изменения:
результаты остаются результатами симуляции, живую проверку смотрят в каждом отчёте.

## Возврат после сбоя или отмены запуска

У неудачного/отменённого задания есть «Настройки этого запуска» и кнопка восстановления.
Она возвращает тексты, аудиторию, размер, режим, seed, параллельность и происхождение
в редактор. Если свой черновик уже изменён, приложение спрашивает о замене.
Новая попытка запускается только отдельным действием пользователя.

Снимок задания доступен после обновления браузера в исходной сессии, пока задание
сохраняется в памяти процесса. После перезапуска сервера или вытеснения задания
он недоступен. Старое задание без снимка открывает текущий черновик с явным пояснением.
Ошибка связи при обновлении прогресса сама по себе не означает ошибку запуска.

## Проверка перед отправкой запросов

На шаге аудитории сводка «Проверьте перед запуском» показывает вопрос, предложения,
нормированные доли и числа профилей, режим, seed и параллельность. Из неё можно вернуться
к текстам. Переход из гипотезы также открывает настройки, а не запускает модель сразу.

Совпадающие после нормализации регистра/пробелов тексты отмечаются предупреждением:
такой запуск пригоден для проверки повторяемости, но не различий текстов. Запуск не блокируется.
Числа профилей и оценка нагрузки показываются только для текущих параметров. Неизвестная
стоимость не заменяется нулём; демо отдельно обозначает гипотетическую LLM-нагрузку.

## Интерпретация сравнения исследований

Выберите два снимка в архиве и нажмите «Сравнить». Подписи «Запуск 1» и «Запуск 2»
обозначают стороны сравнения; дельта равна второму значению минус первое.
Перед таблицей показаны конкретные ограничения: изменения аудитории, модели,
режима, вопроса, текстов и состава предложений, пропуски и проблемы качества ответов.
В строках A/B/C можно раскрыть фактические тексты обоих снимков.

Те же предупреждения включены в JSON-экспорт. Пустая ячейка означает отсутствие
валидных данных, а не нулевой отклик. Сравнение остаётся описательным и само по себе
не подтверждает причинный эффект, статистическую значимость или прогноз спроса.

## Восстановление чтения

При недоступности аналитики отчёт различает ошибку общего разбора и выбранного
сегмента. Сообщения «Готовим…» прекращаются после ошибки; отсутствие аналитики
не обозначается как отсутствие валидных ответов. Кнопка «Повторить загрузку аналитики»
заново читает отказавшую часть из сохранённого снимка и не запускает модель.
Подготовка анкеты, загрузка опроса и сохранённые ответы остаются доступны.

При импорте JSON виден статус чтения файла. Можно выбрать другой файл; завершившееся
позже чтение предыдущего файла не заменит актуальное содержимое. При ошибке чтения
можно повторно выбрать тот же файл. Импорт доступен после успешного чтения.

## Иерархия интерфейса и мобильные действия

Архив выделяет вопрос и следующее действие. «Параметры снимка» раскрывают дату,
модель и размер; у производного запуска есть переход к источнику, если он доступен
в текущем архиве. Порядок списка, поиск и сравнение сохраняются.

Отчёт начинается с «Что сравнивали / Что увидели / Что дальше». В новых отчётах парное сравнение показывает средние оценки ответа «да» по профилям с двумя валидными оценками, размер общей части и интервал при повторной выборке профилей. Матрица сегментов сохраняет доли бинарных ответов. Качество наблюдения
проверяется независимо от приоритета восстановления записи. На телефоне разделы
выстраиваются вертикально, критические ограничения остаются рядом с результатом.

В конструкторе можно раскрыть макет вопроса для участника; он использует текущие
тексты видимых вариантов и не собирает ответы. Распределение аудитории показывает
только актуальный серверный предпросмотр. Мобильные действия находятся над нижней
навигацией, а при фокусе поля возвращаются в поток. После сохранения опроса появляется
подтверждение рядом с просмотренными метриками; ошибка не сопровождается успехом.

# Запуск и эксплуатация локального MVP

[Описание продукта](../README.md) · [Демо](demo.md) · [Архитектура](architecture.md)

Основной интерфейс — React + TypeScript, API и движок — Python. Команды выполняются
из корня репозитория. Поддерживаются Python 3.11/3.12; для сборки рекомендуется Node.js 24.

## Установка и вход

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
npm ci --prefix frontend
npm run build --prefix frontend
# Пропустите создание, если уже есть учётная запись.
python manage.py create-user --username admin --name Администратор --admin
python serve.py
```

Откройте `http://127.0.0.1:8501/`. Пароль при создании вводится скрыто, 12–256 символов.
Существующие аккаунты и `.data/experiments.sqlite3` используются без изменения владельцев.
Node нужен для сборки; после неё интерфейс, API и файлы выдаёт один Python-сервис.
После изменения frontend выполните сборку снова. Отсутствие сборки объясняется launcher сообщением.

Для демо без входа:

```bash
DVOINIK_AUTH_MODE=demo python serve.py
```

Демо использует отдельную `.data/demo.sqlite3`, внешние LLM принудительно отключены.
Это общий демонстрационный архив на локальном сервере; персональные аккаунты используют рабочий режим `local`.
Порт меняется через `DVOINIK_PORT=8502`, путь — через `DVOINIK_STORAGE_PATH`.

### Windows / PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci --prefix frontend
npm run build --prefix frontend
$env:DVOINIK_AUTH_MODE = "demo"
.\.venv\Scripts\python.exe serve.py
```

Для аккаунтов смените режим на `local` и создайте администратора через `manage.py`.
В следующих командах используйте `.\.venv\Scripts\python.exe` вместо `python`.

## Пользовательский путь

1. В каталоге нажмите «Новое исследование». Выберите шаблон или свой сценарий, задайте
   название, вопрос и 2–5 текстов. Контекст и категории отказа находятся в раскрывающемся блоке.
2. Перейдите к аудитории. Доли нормируются; точные количества считает сервер тем же методом,
   что генератор. Ноль исключает сегмент; предупреждение показывает округление до нуля.
3. Запустите. Все предложения оценивают одинаковые профили, прогресс показывает завершённые оценки.
4. В матрице нажмите сегмент или выберите аудиторию в фильтре. График и примеры относятся к ней;
   верхняя сводка — ко всей аудитории. «—» означает отсутствие ответов, 0% — отказ всех ответивших.
5. Посмотрите профили и голоса, загрузите CSV живого опроса. Предпросмотр нужно явно сохранить.
6. «Следующая итерация» копирует снимок в новый черновик; исходный запуск сохраняется.
   Поиск, фильтры и страница каталога сохраняются при возвращении из отчёта.
7. В меню каталога «…» доступны импорт и сравнение двух выбранных запусков; меню отчёта содержит экспорт.

Черновики живут в памяти текущего интерфейса и сохраняются при навигации, включая скрытые D/E.
Перезагрузка страницы может сбросить незапущенный черновик. Выход очищает его; записанные исследования
остаются в SQLite. Browser Back/Forward работают через hash-маршруты.

## Архив и восстановление записи

База по умолчанию `.data/experiments.sqlite3`, файлы SQLite и секреты исключены из Git.
Владелец определяется серверной сессией для импорта, чтения, сравнения, опроса и скачивания.
Администратор управляет аккаунтами, но не получает чужие исследования.

Исходный снимок неизменяем. Проверка опросом сохраняется отдельно с CAS: если другая сессия
обновила предыдущую проверку, сервер возвращает 409. Локальный предпросмотр остаётся для
защищённого скачивания; пользователь может явно сверить CSV заново перед новой записью.

Две задачи выполняются параллельно, восемь ожидают; у владельца один активный запуск.
При ошибке записи готовый результат остаётся создавшей сессии для скачивания и повтора.
Он не считается записанным. Буфер восстановления ограничен; при заполнении новые запуски
отклоняются, а несохранённые результаты не вытесняются. Перезапуск теряет задачи и временные
буферы; записанные исследования сохраняются. Недоступность базы доступа закрывает пространство.

Для резервной копии остановите сервис и скопируйте SQLite. При восстановлении верните файл
по прежнему пути. JSON — независимый перенос отдельного исследования; импорт получает новый ID.

## Аккаунты и доступ

```bash
python manage.py create-user --username colleague --name 'Имя коллеги'
python manage.py reset-password --username colleague
python manage.py disable-user --username colleague
python manage.py enable-user --username colleague
python manage.py list-users
```

Создание и смена пароля выполняются на сервере скрытым вводом. Для автоматизации есть
`--password-file`: храните файл вне Git с правами только владельца. Администратор также
может включать/отключать аккаунты через меню пользователя → «Доступ команды».
Последнего активного администратора отключить нельзя.

Сессия: 30 минут бездействия, 8 часов абсолютного срока. Фоновый опрос прогресса её не продлевает.
Cookie HttpOnly/SameSite Strict; CSRF защищает действия. Выход, блокировка и смена пароля
отзывают сессию и файлы. Если отзыв не записан, интерфейс блокирует работу до повторного выхода.
Поздние ответы прежнего аккаунта не возвращают его данные в новую сессию.

Скачивание: одноразовый URL на 15 минут, cookie действующей создавшей сессии обязателен.
Каждый клик экспорта готовит новый URL. HEAD не расходует его; GET расходует. Секретные ссылки
не пишутся в access log, ответы no-store. Отчёты не размещаются в публичных статических ресурсах.

Старый архив без владельцев автоматически не присваивается вошедшему пользователю.
Миграция и явное присвоение создают резервную копию:

```bash
python manage.py assign-legacy --to admin --record-id ID
```

Все маршруты локальны на 127.0.0.1. Публичный GitHub не означает публичный веб-сервис.
Корпоративный SSO, HTTPS и согласованное сетевое развёртывание — отдельный этап.

## Подключённая LLM

Нужен OpenAI-совместимый `chat/completions` с JSON-ответом и поддержкой
`response_format={"type":"json_object"}`. Например, после установки Ollama:

```bash
ollama pull qwen2.5:7b-instruct
DVOINIK_MOCK=0 LLM_BASE_URL=http://localhost:11434/v1 LLM_MODEL=qwen2.5:7b-instruct python serve.py
```

В локальном режиме переключение модели доступно на шаге аудитории. `DVOINIK_MOCK=0`
меняет начальный режим, демо-аккаунт всегда остаётся mock. `LLM_API_KEY` при необходимости
задаётся только в окружении сервера, не в frontend. `.env.example` показывает имена;
`.env` автоматически не загружается. Тексты и синтетические профили передаются выбранному API.

Первый запрос проверяет API/авторизацию до всей популяции. Таймаут 45 секунд, до двух повторов SDK;
параллельность ограничена. Неверный JSON и ошибки отделены от «нет», показывается покрытие.
LLM-клиент закрывается после запуска. Seed воспроизводит профили и демо, не гарантирует ответы LLM.

## Опрос, импорт и CLI

CSV UTF-8: `segment,variant,decision`, одна оценка на строку; decision 0/1.
В шаблоне решения пустые; заполните их настоящими ответами на сохранённые тексты и удалите
незаполненные строки. React предлагает комплект ZIP с анкетой, CSV и инструкцией через
закрытое скачивание; резервный Streamlit использует тот же генератор пустого шаблона.
Число ответов — число оценок, а не уникальных респондентов. MAE взвешивается по числу
ответов, ранги приводятся к составу опроса; ничьи и отсутствие разброса дают неопределённые метрики.
Валидация не создаётся без данных и не подтверждает их подлинность.

Импорт полного JSON до 5 МБ поддерживает схемы 1/2. Числа, доли, сегменты, категории и примеры
проверяются. Дубликаты ключей и бесконечности отклоняются; интервалы и метрики пересчитываются
из количества ответов. Истинность опроса при этом не подтверждается.

```bash
python cli.py student_card --n 200 --mock --seed 42 --output report.json
python cli.py senior_deposit --n 200 --survey data/survey.csv --output report.json
```

CLI поддерживает 1–10000 профилей, сохраняет полный JSON и не пишет в архив аккаунтов.
Дельты сравнения описательные, без причинного вывода. Файл сравнения содержит оба снимка;
для импорта нужен отдельный отчёт.

## Разработка и проверки

```bash
pip install -r requirements-dev.txt
python -m pytest -q
ruff check .
ruff format --check .
npm test --prefix frontend
npm run build --prefix frontend
npm run format --prefix frontend
```

GitHub Actions проверяет Python 3.11/3.12 и frontend на Node24. Реальная LLM для тестов не нужна.
Тесты React-хуков используют jsdom и Testing Library только как зависимости разработки. Они проверяют смену отчёта во время сохранения, поздние ответы и восстановление полного каталога.

Frontend dev server: `npm run dev --prefix frontend`; Python API должен работать на 8501,
запросы `/api` и `/download` проходят через локальный Vite proxy.

Прежний интерфейс доступен явно и использует тот же архив/аккаунты:

```bash
python serve.py --ui streamlit
```

В Streamlit скачивания обслуживаются вторым локальным сервисом, как раньше.
Node-сборка для этого режима не требуется. Полные границы модулей: [архитектура](architecture.md).

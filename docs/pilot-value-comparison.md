# Лист оценки ценности для партнёра

Заполняется на разговоре с владельцем банковского процесса и уточняется в пилоте.
Пустое значение означает «не измерено». Используйте код кейса и роли, без имён
участников, рабочих банковских материалов и конфиденциальных цен в публичном репозитории.

## Восстановить один реальный кейс

| Вопрос | Что записать |
| --- | --- |
| Какое решение принимала команда? | Код или обезличенное описание продукта, дата, что зависело от итогового исследования |
| Что сделали от постановки вопроса до готовности плана? | Шаги и роли в порядке выполнения, привычные инструменты и разрешённые LLM |
| Где ушли человеко-часы? | Активное время подготовки, проверки и всех переделок по ролям. Отдельно — календарное ожидание и его причины |
| Что осталось после плана? | Набор, сбор ответов, анализ и принятие решения. Какие шаги продолжатся после внедрения |
| Как часто задача повторяется? | Сопоставимые исследования за последние три месяца. Если есть сезонность или внедрение начнётся позже, использовать оценку объёма первого года, а не умножать удачный месяц на 12 |
| Откуда взяты цифры? | Журнал/календарь, фактическая оплата, хронометраж, оценка со слов инициатора. Помечать источник рядом с каждым значением |
| Кто принимает решение о пилоте и закупке? | Роли владельца задачи, бюджета, ИБ и ИТ. Условия согласования и порог эффекта |

После интервью зафиксируйте контрольный процесс до запуска пилота. Если обычный
способ уже включает LLM, не убирайте её из сравнения. Выделенный тест простого
промпта проводите отдельно на новом задании. [Протокол внутренней репетиции](sprint-2-workflow-timing.md)

## Сравнить три решения на горизонте 12 месяцев

Сначала согласуйте одинаковый результат: план пригоден к запуску, вопрос
и критерии проверки понятны, требования доступа, хранения и контроля качества
сопоставимы. Если вариант не выполняет обязательное требование, зафиксируйте
разрыв и затраты на его закрытие до сравнения цен.

| Статья | Оставить текущий процесс | Купить «Двойник» | Разработать внутри |
| --- | --- | --- | --- |
| Время до готовности к использованию, зависимости | | | |
| Активное время на одно исследование по ролям | | | |
| Исследований первого года в сопоставимом объёме | | | |
| Разовые затраты: разработка/интеграция, ИБ, обучение | | | |
| Повторяемые затраты: подписки, поддержка, вычисления, подрядчики | | | |
| Какие живые проверки остаются, и кто за них отвечает | | | |
| Источник оценки и диапазон неопределённости | | | |

`Стоимость труда за год = сумма(часы по роли × полная ставка роли) × число исследований`.
Добавьте разовые и повторяемые затраты, если они ещё не включены в стоимость
труда либо подписку. При разных сроках запуска считайте известный объём по
периодам: до внедрения существующие затраты сохраняются. Не записывайте
высвобождённое время как сокращение бюджета без соответствующего решения.

Результат — три сопоставимых сценария, перечень непроверенных допущений и
условия, при которых есть смысл продолжать пилот. [Сценарный калькулятор покупки](financial-model.md#ценность-для-клиента) показывает порог окупаемости;
полученное число не означает, что банк готов платить такую цену.

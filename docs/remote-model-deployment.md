# Удалённая модель и размещение «Двойника»

У приложения два независимых адреса: адрес, по которому браузер открывает «Двойник», и адрес, по которому бэкенд вызывает модель. Для удалённой модели можно сначала оставить интерфейс локальным. Серверу приложения GPU в этом варианте не нужна: вычисления выполняет провайдер или отдельный сервер модели.

## Проверка подключения к внешнему API

Для первого закрытого показа используем режим probability. Провайдер должен поддерживать OpenAI-совместимый `POST /chat/completions`. Значения ниже — шаблон. URL и идентификатор модели задаёт провайдер, ключ вводится в секреты сервера или в локальное окружение, из которого запущен процесс.

```bash
export DVOINIK_AUTH_MODE=local DVOINIK_MOCK=0
export DVOINIK_LLM_LOOPBACK_ONLY=0
export LLM_BASE_URL=https://model.example.invalid/v1
export LLM_MODEL=provider/model-id
export DVOINIK_ELICITATION=probability LLM_JSON_MODE=auto
# До запуска загрузить LLM_API_KEY из доверенного хранилища секретов.
python cli.py senior_deposit --n 1 --seed 42 --concurrency 1 --output /tmp/dvoinik-remote-smoke.json
python -m dvoinik.run_journal /tmp/dvoinik-remote-smoke.json
```

Ожидаем 3/3 валидных ответов на A/B/C встроенного шаблона и валидную оценку простым промптом. Проверяем расход и ошибки в журнале. Для первого прогона не добавляем параметры LM Studio. Если запускаем SSR, тот же endpoint и ключ должны обслуживать ещё и `/embeddings`, а `LLM_EMBED_MODEL` должен существовать у провайдера. Результаты probability и SSR сравниваем как разные настройки.

Проверено без сетевых вызовов: SDK принимает HTTPS-адрес и ключ при выключенном loopback. При включённом loopback внешний адрес отклоняется. Успешного запроса к реальному удалённому провайдеру пока нет.

## Размещение за HTTPS-прокси

По умолчанию приложение принимает локальные адреса. Для одного адреса стенда задайте
`DVOINIK_PUBLIC_ORIGIN=https://demo.example.org`. В этом режиме допускается только
точное совпадение схемы и хоста, cookie получает Secure, проверка origin для API
сохраняется. Внутренний backend привяжите к loopback и отдавайте наружу только
HTTPS-прокси. Прокси должен сохранять Host и передавать доверенный X-Forwarded-Proto.
В режиме с публичным origin встроенная HTTP-проверка здоровья через localhost не
подходит: проверяйте через настроенный HTTPS-прокси.

Для закрытого стенда используйте `DVOINIK_AUTH_MODE=local`. Оставляем одну инстанцию
с постоянным томом для SQLite и отдельной процедурой копирования и восстановления.
Ключ и endpoint модели задаём на сервере. Перед отправкой настоящих банковских материалов
согласовываем разрешённый состав данных и провайдера. Первый тест выполняем на вымышленном
предложении и синтетических профилях. Текущий Docker Compose для локального Ollama
не нужен для стенда с удалённой моделью.

## Репетиция через модель на Mac

На Mac LM Studio слушает `127.0.0.1:1234`. Обратный SSH-туннель привязывает
`127.0.0.1:12340` на VPS к этому порту на Mac. Бэкенд на VPS обращается к
`LLM_BASE_URL=http://127.0.0.1:12340/v1`; loopback-ограничение остаётся включено.
Туннель не открывает порт модели наружу. Проверить привязку на VPS можно через
`ss -ltn 'sport = :12340'`. Режим `probability` не требует эмбеддингов.

Для репетиции используются аккаунты стенда и вымышленные предложения. LM Studio
должна работать, Mac должен быть онлайн, а SSH-соединение — активно. Режим демо
остаётся запасным вариантом при недоступности Mac. Для оценки доступности облачного
решения нужен отдельный замер с удалённым провайдером.

## Что замерить после подключения

Повторить локальный кейс на удалённой модели с теми же двумя текстами, вопросом, размером, seed и отключённым кэшем приложения. Записать отдельно задержку прогона, число валидных ответов, повторы и фактические input/output токены. Измерить также полный путь через веб-очередь. Считать цену по тарифу выбранного провайдера с учётом входных и выходных токенов. Если меняется модель, это сравнение двух конфигураций, а не измерение сетевой задержки в чистом виде.

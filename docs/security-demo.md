# Показ защиты данных: воспроизводимый сценарий

Цель: показать проверяемые свойства текущего MVP, не требуя настоящих данных банка.
Используются временные тестовые аккаунты Alice/Bob/Admin и синтетические предложения.
Пароли, cookie, CSRF, ручки скачивания и содержимое отчётов в итоговое свидетельство не попадают.

## Автоматический показ

Из корня репозитория, в существующем Python-окружении с `requirements-dev.txt`:

```bash
.venv/bin/python scripts/security_demo.py --output artifacts/security-evidence.json
```

Скрипт запускает выбранные pytest-проверки с изолированной SQLite в системной временной папке.
HTTP-взаимодействие FastAPI TestClient выполняется в процессе, без публикации порта. LLM не
вызывается: используется демо-движок, а отдельная проверка egress подключается только к заведомо
недоступному `127.0.0.1:9` и проверяет адрес. Продуктовый сервер и его архив не используются.
Новых пользователей в рабочей базе команда не создаёт.

Успех: код завершения 0, `passed: true`, все элементы `checks` имеют статус `passed`.
Пропуск теста, ошибка или неполный прогон не считаются доказательством успеха. Счётчики `counts`
и список ID позволяют сопоставить итог с исходным кодом. Исходные логи pytest/XML могут содержать
payload при ошибках: скрипт хранит их только во временной папке и не включает в отчёт.
Если нужно диагностировать ошибку, запустите указанный test ID локально отдельно и не публикуйте
его traceback без проверки. Отчёт фиксирует время запуска, но не является подписанным аудитом.

## Что показывает проверка

| Шаг защиты | Наблюдаемое поведение | Тесты |
| --- | --- | --- |

| Два пользователя | Alice создаёт исследование; Bob и Admin не читают и не экспортируют его; список Bob пуст для чужих записей | `test_api.py::test_owner_and_session_isolation_and_admin` |
| Origin и CSRF | Гость получает 401; запрос другого сайта и POST без CSRF — 403; cookie HttpOnly/SameSite | `test_api.py::test_session_boundary_and_csrf` |
| Сессия при HTTPS | В режиме `DVOINIK_HTTPS_ONLY=1` HTTP отклоняется, а cookie получает Secure при входе и выходе. Проверяется схема ASGI через TestClient. | `test_api.py::test_https_mode_requires_https_and_marks_session_cookie_on_login_and_logout` |
| Выгрузка | Скачать может исходная cookie; HEAD не погашает ссылку, GET погашает; повтор недоступен | sample_cache_import_compare_and_private_download, exports_require_same_cookie_and_expire |
| Очистка временных выгрузок | Предпросмотр считает просроченные записи. Очистка удаляет их из SQLite, действующая выгрузка остаётся доступной. | `test_manage.py::test_purge_expired_exports_previews_without_writing_and_keeps_live_links` |
| Отзыв | Выход, блокировка, сброс пароля и срок прекращают доступ; отзыв во время вычисления/ответа не раскрывает данные | `test_auth.py`: logout_disable_and_reset, idle_and_absolute; `test_api.py`: revoke_during_engine, revocation_before_response |
| Смена аккаунта | Старая вкладка с прежним CSRF не читает данные нового пользователя | old_tab_read_is_rejected_after_browser_cookie_switches_account |
| Опрос | Предпросмотр не меняет сохранённый отчёт; конфликт записи возвращает 409, оставляя прежние данные и экспорт предпросмотра | validation_cas_conflict_preserves_exportable_preview |
| Браузер и сеть | CSP запрещает внешние browser-connect/script; проверенный демо-путь не открывает socket; тест LLM использует только заданный адрес | react_shell_rejects_framing_and_limits_scripts_to_local_assets, `test_no_egress.py` |

Имена в таблице сокращены для читаемости; точный перечень исполняемых ID находится в `CHECKS`
скрипта. Эти проверки уже есть в продуктовой тестовой матрице, скрипт собирает их в показ,
а не заменяет тесты новой имитацией контроля доступа.

## Проверка восстановления SQLite

Вместе с остальными проверками команда выше запускает сценарий восстановления на отдельной тестовой базе. В архив записываются синтетическое исследование и агрегат тестового опроса. SQLite Backup API копирует согласованный снимок с учётом WAL. Снимок восстанавливается в новый файл, затем проверяется целостность SQLite.

Перед стартом приложения тест очищает в восстановленном файле сессии и временные ссылки выгрузок. API отклоняет старую сессию и ссылку. Владелец после нового входа получает тот же отчёт и экспорт, а другой пользователь получает отказ в чтении и выгрузке.

В рабочем регламенте владельцу среды нужно сверить блокировки аккаунтов, смены паролей и права, изменившиеся после точки копирования, до допуска пользователей. Резервная копия SQLite содержит данные архива и учётных записей. Проверка охватывает местную синтетическую базу. Хранение копий, удаление и восстановление в инфраструктуре банка остаются условиями пилота.

## Репетиция закрытия пилота

Сценарий создаёт временную локальную среду с архивом, резервной копией, скачанным JSON и синтетической записью кэша LLM. После блокировки аккаунта API отклоняет прежнюю сессию и ещё действовавшую ссылку. В этот момент все четыре копии остаются читаемыми при доступе к их хранилищу. После остановки приложения тест удаляет принадлежащий ему временный каталог и проверяет отсутствие каталога.

Результат подтверждает отзыв доступа и необходимость учёта каждой копии. Проверка удаления охватывает пути в одной тестовой среде. Для пилота остаются подтверждения по носителям, срокам хранения, устройствам получателей и провайдерам. [Порядок закрытия пилота](pilot-intake.md#закрытие-доступа-и-копий)

## Короткое выступление на защите

1. Показать [карту потоков данных](security.md): браузер → сервис → настроенная модель;
   при внешнем LLM endpoint тексты передаются его оператору. CSV-операция модель не вызывает.
2. Запустить команду; открыть итоговый JSON и показать запрет чужого доступа и отзыв скачивания.
3. Показать UX отдельно: черновик восстановился после reload; при выходе очищается; CSV имеет
   предпросмотр и явное сохранение. Клиентские сценарии проверяются `npm test --prefix frontend`.
4. Назвать оставшиеся условия пилота: egress firewall, TLS, восстановление в инфраструктуре партнёра, retention,
   SSO/аудит и юридическая оценка. Синтетические профили уменьшают потребность в ПДн, но не
   делают произвольный загружаемый текст автоматически обезличенным.

## Границы свидетельства

Это автоматическая проверка выбранных сценариев на текущей машине. Не выполнены независимый
пентест, сертификация, проверка реальной банковской сети и нагрузочное испытание защищённого
развёртывания. Проверка CSP — заголовок/политика; она не ограничивает исходящие запросы сервера.
Загрузка Docker-образов и весов моделей не входит в проверенный offline-путь. Уже скачанный
файл остаётся у получателя после отзыва сессии. Текущие тесты не доказывают безопасное стирание
с диска и резервных копий: функции retention/удаления ещё предстоит реализовать.

# Защита данных и границы развёртывания

Двойник может работать с моделью внутри периметра организации. Это свойство конфигурации и
сетевой инфраструктуры: приложение отправляет тексты на настроенный `LLM_BASE_URL`, который
может быть и внешним. Само приложение не запрещает внешний адрес и не сертифицирует закрытый контур.
Для пилота с банковскими предложениями адрес, модель, прокси и правила исходящего доступа
должны быть проверены владельцем инфраструктуры до загрузки рабочих материалов.

## Какие данные куда идут

| Данные | Где хранятся | Куда передаются |
| --- | --- | --- |
| Черновики: вопрос, предложения, аудитория, параметры | `sessionStorage` текущей вкладки, ключ владельца; восстановление после reload, очистка при выходе/потере сессии | В сервис при запуске/оценке; затем в настроенную модель при LLM-запуске |
| Тексты предложений, вопрос, настройки и результат | SQLite `DVOINIK_STORAGE_PATH`; локальные файлы экспорта у скачавшего пользователя | В модель через `LLM_BASE_URL`; в скачиваемое резюме/JSON/CSV по запросу владельца |
| Синтетические профили | Генерируются в памяти, ограниченный пример профилей сохраняется в снимке | В модель через `LLM_BASE_URL` |
| Реакции модели и эталонные фразы SSR | Результат/агрегаты в снимке, необязательный кэш LLM на диске | В SSR реакции и эталонные фразы передаются в `/embeddings` того же API-клиента; модель `LLM_EMBED_MODEL` |
| Кэш LLM | `DVOINIK_LLM_CACHE_PATH`: хеш ключа запроса и проверенный ответ | Самостоятельно не передаётся; ответ может содержать чувствительные фрагменты предложения |
| CSV опроса | В памяти браузера до ухода/сохранения; сервис разбирает CSV, предпросмотр держит в памяти сессии | В сервис для предпросмотра/сохранения; не отправляется в LLM этой операцией |
| Сохранённая проверка опроса | SQLite: агрегированные ячейки сегмент/вариант, количества, дата и метрики; исходный CSV в снимок не записывается | В экспорт по действию владельца |
| Аккаунты и сессии | SQLite; пароли Argon2id, токены/ручки экспорта в базе в виде хешей | Сессионная cookie браузера ↔ сервис; пароль передаётся при входе |

Персональные данные реальных клиентов для основной функции не требуются. Профили синтетические,
а CSV ожидает `segment,variant,decision`. Это не автоматическое обезличивание: свободный текст
предложения, имя файла или загруженные лишние поля всё равно могут содержать чувствительные данные.
Не добавляйте персональные данные в рабочие материалы; доступ к браузеру и файлам экспорта также
нуждается в контроле. `sessionStorage` доступен скриптам этого origin, а не является шифрованным сейфом.

## Реализованные меры и проверяемые свидетельства

- Локальные аккаунты, роли `analyst/admin`, отдельные архивы владельцев. Администратор управляет
  аккаунтами, но не получает автоматически содержимое их исследований. ID из чужого отчёта не даёт доступ.
- Argon2id для паролей, ограничение попыток входа, серверные сроки сессии, отзыв при выходе,
  блокировке и смене пароля. Автополлинг запуска не продлевает бездействующую сессию.
- HttpOnly и SameSite=Strict cookie; изменяющие API-запросы требуют CSRF-токен и допустимый origin.
  Cookie текущей локальной HTTP-конфигурации **не имеет Secure**. Сетевое развёртывание требует
  отдельно настроенного TLS-шлюза и проверки cookie/проксирования, это не готовый production-рецепт.
- Одноразовые скачивания: срок 15 минут, разрешённые форматы, session-cookie binding в React,
  повторный GET и отзыв сессии прекращают доступ. Скачанный файл невозможно отозвать средствами сервиса.
  В резервном Streamlit ссылка является bearer-секретом действующей сессии: не пересылайте её.
- CSP браузера разрешает подключения/скрипты только своего origin; no-store, nosniff, запрет framing.
  CSP не ограничивает исходящие соединения Python-процесса. Локальная HTTP-граница принимает только
  localhost/127.0.0.1; опубликованный домен за прокси требует отдельного проекта сетевого доступа.
- CSV проверяется до сохранения; предпросмотр отделён от записи. Защита от конкурентной замены
  сохраняет прежнюю проверку при конфликте. Новая сохранённая проверка заменяет старую без истории.

Команда `python scripts/security_demo.py` выполняет выбранные реальные тесты с отдельными временными
аккаунтами и SQLite, затем выдаёт обезличенный JSON. Она не использует производственные данные и
не запрашивает внешнюю LLM. Инструкция, покрытие и ограничения — [security-demo.md](security-demo.md).
Проверки клиентского хранения черновиков находятся отдельно в `frontend/src/app/draft-preservation.test.tsx`.

`tests/test_no_egress.py` подтверждает отсутствие socket-соединений в проверенном демо-пути и адрес
подключения в отдельном LLM-пути с недоступной локальной моделью. Это не firewall, не полный
анализ всех зависимостей и не доказательство отсутствия утечек во всех возможных конфигурациях.
SSR и поведение клиента API проверяются отдельно в `tests/test_ssr.py` с mock transport.

## Локальное развёртывание

```bash
docker compose up -d
docker compose exec ollama ollama pull qwen2.5:7b-instruct
docker compose exec ollama ollama pull bge-m3
docker compose exec app python manage.py create-user --username analyst --name "Аналитик"
```

Порт приложения опубликован на `127.0.0.1:8501`, порт Ollama не опубликован на хосте. Однако
стандартная Docker-сеть сама по себе не блокирует исходящий интернет. Загрузка образов/моделей
требует сети; для закрытого контура их сначала доставляют через одобренный процесс и ограничивают
исходящий доступ сетевыми правилами. Режим demo не эквивалентен проверенному LLM-результату.

## Хранение, резервные копии и удаление

SQLite, кэш и резервные копии содержат рабочие данные. Владелец развёртывания задаёт права ОС,
шифрование тома, доступ сервисной учётной записи, срок хранения, место/шифрование резервных копий
и проверяет восстановление. Согласованную копию живой SQLite делают через SQLite backup API,
а не копированием только основного файла при активном WAL. В репозитории нет настроенного
регулярного резервного копирования и доказанной процедуры disaster recovery.

Выход удаляет локальные черновики и отзывает сессию; он **не удаляет** сохранённые исследования.
Блокировка аккаунта также не стирает архив. Отдельного пользовательского удаления исследования,
автоматического retention и гарантированного уничтожения кэша/резервных копий сейчас нет.
Для удаления данных в пилоте нужен регламент оператора, охватывающий архив, кэш, копии и экспорты.
Проверка такой процедуры — условие пилота, а не уже выполненная функция.

## Открытые вопросы перед банковским пилотом

- Корпоративный SSO, журнал действий и роли совместного просмотра.
- TLS, Secure-cookie, конфигурация доверенного reverse proxy и ограничение сетевого egress.
- Шифрование томов, резервные копии с проверкой восстановления, retention/удаление, управление секретами.
- Нагрузочные проверки, мониторинг и восстановление после сбоя процесса; задания и предпросмотры сейчас в памяти.
- Инвентаризация данных и юридическая оценка применимых требований комплаенса организацией.

Эти меры и тесты дают технические свидетельства для MVP. Они не являются пентестом,
сертификацией безопасности или заключением о соответствии нормативным требованиям.

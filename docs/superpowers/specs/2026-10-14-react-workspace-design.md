# Двойник: React-интерфейс и Python API

Согласованное пользователем направление: переход с Streamlit на React + TypeScript и FastAPI, меньше одновременно видимых действий, сохранение возможностей MVP. Этот документ описывает целевое поведение; наличие документа само по себе не означает завершённую миграцию.

## Пользовательский путь и оформление

В рабочем пространстве доступны исследования, создание исследования и методология. Управление аккаунтами находится в меню пользователя и доступно администратору. В каталоге главное действие — «Новое исследование», строки открывают отчёт; импорт и сравнение находятся среди дополнительных действий. Поиск, фильтры режима/опроса и страница каталога сохраняются при возвращении из отчёта.

Создание состоит из двух рабочих шагов: предложения и аудитория. На первом выбирают один из семи шаблонов либо свой сценарий, задают вопрос, контекст и 2–5 текстов. На втором задают размер аудитории и относительные доли семи сегментов, видят точные количества после нормализации. Главное действие — запуск. Seed, параллельность и категории отказа находятся в дополнительных параметрах. Черновик сохраняется при навигации внутри приложения, включая скрытые варианты D/E; выход очищает его.

Процесс запуска показывает фактические завершённые оценки движка. Готовый отчёт открывается после завершения. В отчёте первое действие — «Следующая итерация», копирующая полный сохранённый снимок в новый черновик. JSON/CSV и сравнение доступны в меню. Основное представление — матрица сегментов и предложений, переключение аудитории, интервалы, причины отказа и подборка реплик. Дополнительные вкладки содержат профили, все сохранённые голоса и проверку опросом.

Визуальная система: светлая рабочая поверхность #F3F5F9, белые области #FFFFFF, графитовый текст #192D40, основной синий #2457D6, бирюзовый #137D76, сиреневый #7D65B4. Цвет предложения последователен в редакторе, таблице и графиках. Типографика Avenir Next / Segoe UI / системный sans-serif; внешние шрифты и CDN не требуются. Выразительность создают заголовки, реальные данные и смена состояний. Анимация не мешает чтению и отключается при reduced-motion.

Нативные семантические элементы, подписи контролов, видимый фокус, Escape для меню/диалогов, возврат фокуса и работа с клавиатуры обязательны. На ширине 390 px нет горизонтального переполнения страницы; широкая матрица прокручивается внутри своего блока. Демо и отсутствие живой проверки обозначаются рядом с результатом.

## Границы модулей

- `frontend/`: React, TypeScript, Vite; API-клиент, типы, управление черновиком, страницы и CSS.
- `dvoinik/api.py`: создание FastAPI приложения, HTTP-контракты, проверка сессии и владельца, статическая выдача собранного frontend.
- `dvoinik/jobs.py`: ограниченная очередь запусков, прогресс, готовые и ожидающие сохранения снимки.
- `runs`, `engine`, `population`, `experiments`, `storage`, `auth`, `validate`, `comparison`, `insights`: существующие проверенные расчёты и данные, без зависимости от React.
- `serve.py`: локальный запуск новой версии и явный запуск прежнего Streamlit как резервного интерфейса.

## HTTP-контракт

Все маршруты `/api` возвращают JSON. Ошибки имеют `detail` с понятным сообщением; ошибку сохранения нельзя выдавать за успешное сохранение. Числа проверяются сервером; владелец задаётся только серверной сессией. Снимок JSON сохраняет существующий формат версии 2.

| Метод и маршрут | Запрос и результат |
| --- | --- |
| GET `/api/session` | `{user: {id,username,name,role}, csrf_token, mode, model, default_mock}`; в локальном режиме без входа 401, в демо создаётся HttpOnly-сессия |
| POST `/api/login` | `{username,password}`; устанавливает cookie, возвращает тот же объект сессии |
| POST `/api/logout` | отзыв сессии и связанных экспортов; cookie удаляется только после успешного отзыва |
| GET `/api/catalog` | `{scenarios,segments}` — исходные тексты и публичные характеристики сегментов |
| POST `/api/preview` | `{population,n}` → `{counts,shares}`; нормализация и округление из существующего кода |
| GET `/api/experiments` | `{records}` из архива владельца; клиент выполняет поиск, фильтры и пагинацию |
| GET `/api/experiments/{id}` | полный снимок; чужой или неизвестный ID → 404 |
| POST `/api/import` | `{content}` с JSON до 5 МБ → импортированный снимок с новым локальным ID и исходным происхождением |
| GET `/api/sample/{key}` | демонстрационный снимок без автоматической записи в архив |
| POST `/api/runs` | `{scenario_key,scenario,n,mock,seed,concurrency}` → 202 `{id,status,done,total}` |
| GET `/api/runs/{id}` | `{id,status,done,total,record,error,saved}`; доступ только создавшей сессии |
| POST `/api/runs/{id}/retry` | повторное сохранение готового снимка при прежнем действующем доступе |
| POST `/api/insights` | `{record_id,segment}` → `{report,summary,quality}`; сегментные интервалы и статус считает Python |
| POST `/api/compare` | `{left_id,right_id}` → `{left,right,comparison}`; оба снимка проверяются по владельцу |
| POST `/api/experiments/{id}/validation/preview` | `{csv}` → `{record,base_validation,preview_id}` без записи; ID фиксирует точный предпросмотр вкладки |
| PUT `/api/experiments/{id}/validation` | `{csv,base_validation}` → сохранённый снимок; CAS сравнивает предыдущую проверку, конфликт → 409 |
| POST `/api/export` | `{record_id,format,kind,preview_id?}` → `{url}`; format `json`/`csv`, kind `record`/`validation`/`survey-template`/`preview`; для preview обязателен его ID, только доступный серверный снимок |
| GET `/api/recovery` | `{jobs}` — готовые несохранённые результаты только создавшей cookie-сессии; восстановление после обновления страницы |
| POST `/api/runs/{id}/export` | экспорт готового, в том числе несохранённого, результата принадлежащего сессии |
| POST `/api/compare/export` | `{left_id,right_id}` → одноразовая ссылка на JSON сравнения |
| GET `/api/users` | `{users}` только администратору, без хешей паролей |
| PUT `/api/users/{id}/active` | `{active}` только администратору; блокировка отзывает доступ |
| GET/HEAD `/download/{handle}` | существующая одноразовая выдача с проверкой срока и связанной сессии |

Сервер не принимает готовые проценты в качестве результата запуска и не доверяет метрикам загруженного опроса. В демо `mock` принудительно true. Нулевое количество согласий и отсутствие ответов различаются; интервалы считаются из валидных ответов. Общие причины отказа не становятся статистикой выбранного сегмента. Экспорт всегда полный и не зависит от фильтра UI.

## Сессии и данные

Cookie HttpOnly, SameSite Strict, path `/`; токен не передаётся в JSON, URL или localStorage. Записывающие запросы требуют защиты от CSRF; login и demo bootstrap проверяют происхождение запроса. API и сборка обслуживаются одним локальным origin. Сервис слушает только 127.0.0.1; сетевой банковский доступ и SSO не добавляются этим изменением. Персональные архивы, администратор без доступа к чужим запускам, 30 минут бездействия и 8 часов абсолютного срока сохраняются. Фоновый опрос прогресса не продлевает бездействующую сессию.

Одновременно работают не более двух задач движка и одна активная задача на владельца. Доступ проверяется до запуска, при прогрессе, перед возвратом и при записи результата. Выход или блокировка останавливают доступ к задаче. Очередь и несохранённые результаты находятся в памяти процесса; перезапуск прерывает их, а записанные исследования остаются в SQLite. При недоступности записи готовый результат остаётся доступен создавшей сессии для повторного сохранения и защищённого скачивания. Чужая сессия не получает его.

Текущие базы, аккаунты, пароли и владельцы используются без переноса в новую базу. Перед переключением рабочего сервиса делается локальная резервная копия; секреты, базы, node_modules и временные артефакты исключены из Git. Импорт опроса сохраняет сравнение предыдущей версии. При конфликте UI оставляет локальный предпросмотр и предлагает скачать его, не перезаписывая серверную проверку.

## Выпуск и проверка

Сначала новая версия проверяется на отдельном порту и отдельной демо-базе. После API-тестов, сборки и проверки полного пути в браузере React становится интерфейсом по умолчанию. Streamlit остаётся доступен явно как резервный путь. Node требуется для сборки, Python — для сервера; production не запускает Vite dev server. Команды запуска обновляются в README и технической документации.

Критерии: вход/выход, изоляция двух аккаунтов, отзыв доступа, CSRF, ограничение очереди, семь шаблонов, свои 2–5 предложений, точная аудитория, прогресс, архив, импорт, полные экспорты, сравнение, CSV preview/save/conflict, повторное использование снимка, мобильная и клавиатурная навигация. Существующие 153 проверки сохраняются; новые API-проверки используют изолированную базу и демо/HTTP-транспорт. Реальная LLM-точность и банковский пилот этим релизом не подтверждаются.
